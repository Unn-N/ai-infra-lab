# 17 · 双缓冲的带宽与 SM 指标对照

2026-11-07。用户希望验证双缓冲是否提高带宽占用，以及先前长方形输入加速是否伴随 SM 工作效率变化。先限定结论：五组性能样本不足以推出一个完整的小输入适用范围；带宽、SM 活跃、指令发射是不同指标。

## 对象与方法

原版 gemm_self_re.cu 对照独立 gemm_self_double_buffer.cu；配置均为 OUTPUT_TILE=64、K_TILE=32、THREAD_TILE=4。选大方阵 2048³，以及上轮加速的 128×1024×512。

独立入口按原测量入口随机种子及序列生成同样输入；一次分配上传，先执行六次 kernel，再采第七次。两版均以 -O3 -lineinfo -arch=sm_120 编译。Nsight Compute 使用 application replay、cache-control none、clock-control none，不清缓存、不锁时钟；GPU 工作全部顺序执行。每组两轮，第二轮反转版本顺序。

先采 20 项 DRAM/L2/SM/停顿指标。大方阵双缓冲第二、三次宽指标采集出现 L2 hit=100.01%、100.07%，属于不可能的比例；未当作有效命中率解释。多轮重放且缓存/时钟不控制可能使组成指标不一致，因此另做仅含 gpu duration、dram bytes、bytes/s、bytes pct-of-peak 四项指标的定点采集。下方带宽结论取自这组较少指标的独立采集，完整异常记录保留，不混入干净数据范围。

## 定点带宽结果：两轮范围

### 2048×2048×2048

| 指标 | 原版单缓冲 | 异步双缓冲 |
|---|---:|---:|
| DRAM 字节吞吐（GB/s） | 41.83—46.35 | 30.87—33.72 |
| DRAM 字节带宽占持续峰值（%） | 6.23—6.90 | 4.60—5.02 |
| 该采集中的耗时（ms） | 1.4307—1.4347 | 1.5667—1.5703 |
| 该采集中的 DRAM 总流量（MiB） | 57.07—63.42 | 46.12—50.50 |

### 128×1024×512

| 指标 | 原版单缓冲 | 异步双缓冲 |
|---|---:|---:|
| DRAM 字节吞吐（GB/s） | 64.31—67.22 | 89.64—93.05 |
| DRAM 字节带宽占持续峰值（%） | 9.58—10.02 | 13.36—13.90 |
| 该采集中的耗时（ms） | 0.0449—0.0451 | 0.0257—0.0284 |
| 该采集中的 DRAM 总流量（MiB） | 2.76—2.89 | 2.28—2.43 |

这里的百分比专门使用 dram__bytes.sum.pct_of_peak_sustained_elapsed，是字节速率相对工具持续峰值的比例。此前 notes/15 使用 cycles_active/cycles_elapsed 描述内存活跃周期；两者不是同一个量，不能互换。也不把 dram__throughput 汇总指标一概当作字节带宽占比，因为 throughput 取其组成指标中的最大百分比。

两轮都显示：**长方形输入的 DRAM 吞吐及占峰值比例提高；大方阵未提高，反而下降。** 两种情况都远未达到 DRAM 带宽饱和。带宽变化是观测结果，不把更高带宽本身作为优化目标；目标仍是相同结果的完成时间。

## SM 与 L2 辅助指标

以下来自先前宽指标采集，与定点带宽表不是同一次运行。长方形两轮数据：

| 指标 | 单缓冲 | 双缓冲 |
|---|---:|---:|
| SM 指令发射比例，elapsed 周期口径 | 17.18%—17.45% | 30.44%—30.47% |
| SM 有 warp 在途的活跃周期比例 | 62.63%—64.96% | 63.54%—64.22% |
| L2 sector 处理吞吐（sector/s × 32 B，GB/s） | 219.14—222.08 | 378.20—378.52 |

这支持“该长方形中，现有 SM 上的工作推进效率提高”，不能理解为用了更多 SM：该 grid 始终只有 32 个 block，没有因双缓冲增加 block 数。SM 活跃比例本身也没有明显上升，提升主要体现在指令发射这一项观测。

对大方阵，第一轮未出现不可能命中率的宽指标对照中，指令发射比例从 71.73% 降到 63.86%，L2 sector 吞吐从 833.67 降到 724.70 GB/s。其他宽指标采集因存在不一致，不用来给出稳定的精确 L2 结论；定点带宽的两轮仍一致显示 DRAM 字节吞吐未提高。

不同加载指令会改变停顿归类，不能仅由 long scoreboard 降低就声称隐藏了等量墙钟等待。此次没有隔离“异步搬运指令本身”与“双缓冲重叠”各自的贡献，也未唯一定位大方阵回退原因。
