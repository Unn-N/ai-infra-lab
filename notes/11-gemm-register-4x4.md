# 11 · 输出块扩大到 64×64，每线程 4×4

2026-11-07，用户预测大输入会受益，并授权与上一版本对照。当前 `gemm_self_re.cu` 配置变为 `OUTPUT_TILE=64, K_TILE=32, THREAD_TILE=4`，block 仍是 16×16。只改两个配置值及对应注释，沿用前一步的协同加载、累加和写回算法。

## 正确性

手算小例子通过；CPU 全输出对照的 `(M,N,K)=(1,1,1)、(32,32,32)、(37,45,67)、(64,33,96)、(63,65,33)、(65,67,31)、(129,130,35)` 全部通过，覆盖 4×4 小块边缘与跨 64 输出 tile 的情况。全输出测试使用可精确表示的小数。同期六次性能测量进程的五组随机正负输入，全部通过 64 点 CPU double 抽查。抽查不代替全面验证。

## 同期性能对照

测量入口与输入不变，GPU 缓冲区重复使用且不冲 L2，不计分配/拷贝。每版本三次进程，顺序 `2×2→4×4`、`4×4→2×2`、`2×2→4×4`，每次每组预热 5 次、测 3 轮，每轮 20 次启动。下表取九个批次平均耗时的中位数。

| M,N,K | 输出32 / 每线程2×2 / ms | 输出64 / 每线程4×4 / ms | 加速比（旧 / 新） |
|---|---:|---:|---:|
| 128,128,128 | 0.008579 | 0.029304 | 0.293× |
| 512,512,512 | 0.045568 | 0.043640 | 1.044× |
| 2048,2048,2048 | 2.589144 | 1.649162 | 1.570× |
| 128,1024,512 | 0.028032 | 0.033888 | 0.827× |
| 127,513,257 | 0.012670 | 0.020984 | 0.604× |


本次 2048³ 加速约 1.57×，支持用户对这组大方阵的预测；512³ 约 1.04×，改善较小。长方形和非整齐输入均退步；128³ 也退步且波动明显，不将“大输入会更快”扩大为所有形状的结论。

## 资源和分工变化

```text
2×2: threads/block=256 registers/thread=42 shared/block=8192 local/thread=0 theoreticalBlocks/SM=5
4×4: threads/block=256 registers/thread=62 shared/block=16384 local/thread=0 theoreticalBlocks/SM=4
```

每线程寄存器从 42 增至 62，shared 从 8 KiB 增至 16 KiB，理论驻留 block 数由 5 降至 4，查询到的 local memory 仍为 0。驻留能力下降，大方阵仍加速，说明不能仅凭理论 occupancy 的高低判断总性能。

每个输出 block 覆盖面积扩大四倍，grid 的 block 数随之减少：

| M,N,K | 输出32的 grid block 总数 | 输出64的 grid block 总数 |
|---|---:|---:|
| 128,128,128 | 16 | 4 |
| 512,512,512 | 256 | 64 |
| 2048,2048,2048 | 4096 | 1024 |
| 128,1024,512 | 128 | 32 |
| 127,513,257 | 68 | 18 |


本卡有 48 个 SM。例如 128×1024 输出现在只有 32 个 block，127×513 输出只有 18 个，不能同时为全部 SM 各提供一个普通 block。这为小/窄输出的退步提供具体解释线索。更大的边缘 tile 也可能增加无效计算；未用 profiler 分离这些因素的实际贡献。

两版 K_TILE 都是 32。新版本每轮输入块元素数增加两倍，支撑的乘加次数增加四倍；每线程每个 k 读取四个 A 与四个 B，可更新十六个输出。数据复用收益与资源/并行度代价共同存在。
