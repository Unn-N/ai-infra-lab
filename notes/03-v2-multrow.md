# 03 · v2：多行共享 block + warp 内归约

> 解决的是 02 里那条：短行为什么慢。结论：**用户自己推的方向是对的，而且是主因。**

---

## 一、改了两件事

| 改动 | 内容 |
|---|---|
| **多行共享 block** | 设 `W` = 每行用几个 warp，则每 block 处理 `R = 8 / W` 行 |
| **归约换两层** | warp 内 `__shfl_down_sync`（5 步，零屏障）+ 跨 warp 用 shared（**2 次**屏障，原来 9 次） |

`W=1 → R=8`：一个 warp 一整行，8 个 warp 全忙。
`W=8 → R=1`：八个 warp 合干一行（v1 的形状）。

---

## 二、结果：8192 × 128

| 配置 | 时间 | 相对上一行 |
|---|---|---|
| v1：树形归约 + 9 次屏障 | 0.0665 ms | — |
| v2 `W=8`：shuffle + 2 次屏障 | 0.0407 ms | **1.63×** |
| v2 `W=1`：一个 warp 一行 | **0.0134 ms** | **3.04×** |
| 合计 | | **4.96×** |

**归约改造 1.6 倍，多行 3 倍。多行是主导项。**

`maxerr` 全部 1e-9 量级，正确性没问题。

---

## 三、分界点

| N | `W=1` | `W=8` | 谁赢 |
|---|---|---|---|
| 128 | 0.0134 | 0.0407 | **W=1 快 3.0×** |
| 512 | 0.0529 | 0.0665 | W=1 快 1.26× |
| 2048 | 0.2570 | 0.2246 | W=8 快 1.14× |
| 8192 | 1.8600 | 0.9274 | **W=8 快 2.0×** |

**分界在 512 和 2048 之间。**

### 一个没有完全被解释的点

按“每线程 4–8 个元素”的规则：

- `N=128, W=1` → 4 个/线程 ✓
- `N=512, W=1` → **16 个/线程**，按规则算超了，但它**赢了**（0.0529 < 0.0665）
- `N=8192, W=1` → 256 个/线程，输得很惨（0.86× 变慢）

**所以“4–8”只是个粗略范围，不是硬规则。**

一个假设（未验证）：真正限制的可能是**累加链的串行度**。`m = fmaxf(m, x)` 是一条依赖链，16 个元素还算短，256 个就变成很长的串行链，指令级并行被掐死。

## 四、测量上的两个坑

### 坑 1：小工作集的 `%spec` 系统性偏高

```
flush 冲掉 L2 → kernel 读 x（从显存）
              → kernel 写 y（进 L2，标脏）
              → 下一次 flush 才把它挤出去写回   ← 这段不计入 kernel 时间
```

工作集越小，写回被“藏”得越干净：

| 工作集 | 例子 | %spec |
|---|---|---|
| 33 MB | 2048×2048 | 99.1% |
| 134 MB | 8192×2048 | 88.9% |
| 537 MB | 8192×8192 | 86.1% |

**99% 贴着理论峰值是不正常的，说明有一部分流量没算进来。**

→ **同尺寸内的横向对比仍然有效**（`W=1` vs `W=8` 在同样的偏差下测），跨尺寸的纵向对比要打折扣。
→ 要真实流量只能上 `ncu` 看 `dram__bytes_*`，或把张量做得远超 L2。

### 坑 2：微秒级的测量不可信

`512×128` 用了 `W=1`，两次运行给出 **0.0116 ms** 和 **0.0039 ms**——同一份代码，差 3 倍。

原因：`M=512, R=8` → 只有 **64 个 block**，还不到 48 个 SM 的两倍。启动开销和调度尾巴占满全程，测的是噪声。

**教训：block 数太少时，测的不是 kernel，是启动。**

---

## 五、结论

1. **“用多行把 warp 填满”这个方向是对的**，`N=128` 从 19% 走到 93%（数字偏高，见坑 1）。
2. 长行几乎没动（0.9340 → 0.9274），符合预期——它早就在带宽墙上，去掉屏障没有更多可拿。
3. **一个旋钮，两个用途**：`W` 小 → 行内并行少、并发行多（适合短行）；`W` 大 → 行内并行多（适合长行）。
4. 分界点大约在 `N = 512 ~ 2048`。
