# 13 · 输出分块、数据复用与任务并行度的取舍

记录时间：2026-11-07 16:25，Asia/Hong_Kong。整理自用户在寄存器分块实验后对大小输入、任务结构和配置选择的思考。

## 核心判断

用户提出：扩大输出块可以提高复用，但面对较小输出时，独立任务可能不够。这属于任务划分中的结构性取舍；不应要求一个固定配置在所有输入上始终最优。数据量较小时，可能更需要关注能否提供足够的有效并行工作。

经讨论，保留这个主要判断，并进一步限定为：

> 根据输入的形状和实际负载，在数据复用、可用并行任务、资源需求与组织开销之间选择配置。输出块扩大后，复用可能提高，但 block 总数减少；不同输入上，各项收益和代价的分量不同。

## 先分清三种大小

| 大小 | 由什么决定 | 对当前实现意味着什么 |
|---|---|---|
| 输出规模 | M×N | 有多少独立输出元素，可划出多少输出 block |
| 输入数据量 | A 为 M×K，B 为 K×N | 需要容纳和读取多少输入，不能仅由输出规模判断 |
| 计算量 | 约 2×M×N×K FLOP | 每个输出沿 K 做多少乘加，以及总计算工作量 |

M、N 较小而 K 很长时，计算量和输入数据量仍可能很大，但独立输出任务仍较少。因此讨论“小输入”时要明确指哪一项。

## 扩大输出块的双向影响

在本轮保持 K_TILE=32、block=16×16，输出块从 32×32 扩为 64×64 的设计中：

- 一个 block 每轮的有效输入块元素数翻倍，支撑的乘加次数变为四倍，块内复用增加；每线程 4×4 输出也比 2×2 有更多线程内复用。
- 每线程的累加器和寄存器需求增加，shared 用量增加，理论驻留能力可能下降。
- 同一份 C 被分成的 block 更少。当前 grid block 数为 `ceil(M/OUTPUT_TILE) × ceil(N/OUTPUT_TILE)`，与 K 的长度无直接关系。
- 边缘输出块可能包含更多无效位置，带来额外的补零和计算。

## 已有实验依据

| 输出形状 M×N | 输出块32的 block 数 | 输出块64的 block 数 | 本轮观察 |
|---|---:|---:|---|
| 2048×2048 | 4096 | 1024 | 扩大后同期约 1.57× 加速 |
| 128×1024 | 128 | 32 | 扩大后退步 |
| 127×513 | 68 | 18 | 扩大后退步 |

本卡有 48 个 SM。仅考虑当前普通 kernel，32 个 block 至多同时分布在 32 个 SM 上，18 个 block 至多分布在 18 个 SM 上；即使每块内部做得更高效，也可能因缺少独立任务而不能利用全部 SM。该任务数量关系是确定的，但它解释了多少实测退步，尚未分离验证。

完整对照与原始数据见 [64×64 / 每线程4×4 实验](11-gemm-register-4x4.md)。不同阶段的数据不能直接拼成严格的总加速比，小尺寸测量仍存在波动。

## 对原直觉的三点细化

1. **增加 block 内线程数，与增加可分配到不同 SM 的 block 数不同。** 同一个普通 block 在一个 SM 上执行；只有少数 block 时，单纯增加每块线程数不能让这几个 block 分散到更多 SM。
2. **数据量小不等于读取和组织成本可以忽略。** 访存仍有延迟，启动、同步和调度也有成本。划分过碎可能加重开销，不是线程或 block 越多越好。
3. **选择不同 tile 是合理策略，但不是所有结构问题的唯一解。** 也可以改变其他任务划分；本项目目前先研究有限的配置，不展开额外算法。相同的参数化 kernel 代码可以编译出多个配置，不一定维护多份独立实现。

## 当前结论的边界

已支持：固定配置确实存在逐输入的收益与退步；扩大分块同时影响复用、资源与任务数量，根据形状选择配置有明确动机。

尚未证明：任意输入的最佳配置、各类退步的唯一瓶颈、理论驻留率与实际利用率的精确关系。没有把本次解释提升为“已经证实是显存带宽受限”或“计算能力已经用满”。

接下来的实验仍以固定口径、逐输入比较为主；保留多种候选配置及其适用证据。按输入自动选择配置尚未实现，K_TILE=16/32/64 的下一轮对照也尚未开始。
